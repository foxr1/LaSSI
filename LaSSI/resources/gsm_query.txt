// Identifies if a verb has an active object or complement
has_active_object = (V)--[l:dobj||ccomp||xcomp||obj]->(O)
        where (ℓ 0 @ V = verb)
       ↪ (V);

// Identifies if a verb has an auxiliary verb
has_aux = (V)--[l:aux]->(A)
        where (ℓ 0 @ V = verb)
       ↪ (V);

// Identifies a verb that is BOTH the target of an incoming acl edge
// AND has an auxpass child (i.e. a "being VBN" passive participle inside a reduced-relative
// or existential clause, e.g. "There are X being carried out at Y" — `carried` matches).
// Used as a guard for p4: such verbs are true passive participles and must not be lifted
// into a kernel by p4 (which would put the obl/location as target and the AND-subject from
// the parent existential as source — wrong). They should be handled at the kernel-building
// layer instead. Verbs that are acl targets WITHOUT auxpass (e.g. transport_005's
// "concerns identified during inspection") still go through p4 unchanged.
has_incoming_acl_passive = (B)--[l:acl]->(V)
                           (V)--[aux_l:auxpass]->(A)
        where (ℓ 0 @ V = verb)
       ↪ (V);

// Identifies a verb that governs a PASSIVE SUBJECT (has an outgoing `nsubjpass`
// edge). Used as a guard for p4 on the *source* B of p4's incoming edge: if the
// node feeding into p4's candidate V is such a verb, then V is that verb's
// nsubjpass patient (a noun argument), not a subject-less predicate, and p4 must
// not lift it into a kernel.
//   Pathology: "Roadworks on Fern Drive involving pipe replacement are expected
//   to end on 30 April ...". Here B = "expected" (nsubjpass → "Roadworks"); the
//   subject "Roadworks" carries an nmod chain, so p4's `(>> V)` aggregate (and
//   intermediate node re-creation) makes a V-side `unmatched` guard miss it —
//   but B = "expected" is a stable node, so guarding on B is reliable. Genuine
//   subject-less verbs targeted by p4 are not fed by an nsubjpass-governing verb,
//   so this is a no-op for them.
has_nsubjpass_child = (B)--[l:nsubjpass]->(C)
        where (ℓ 0 @ B = verb)
       ↪ (B);

// RULE: Generalised garden-Path semantic correction
// If a verb has an active subject (nsubj) but NO active object and NO auxiliary,
// AND it is explicitly tagged as a past participle (VBN),
// it is highly likely a misparsed reduced relative clause. We forcefully invert
// the relationship to a passive subject (nsubjpass).
fix_garden_path = (V)--[l:nsubj]->(S)
        where ((ℓ 0 @ V = verb) ∧ ((FILL ( 𝜋 xpos @ V ) = VBN) ∧ ((V unmatched has_active_object . V) ∧ (V unmatched has_aux . V))))
       ↪
          set (φ nsubjpass , V) as S
          del l
          (V);

// RULE: Normalise standard reduced relative clauses (Catches cases where the parser actually outputs 'acl')
// Fires unconditionally for any S--[acl]-->V where V is a verb.
// Also propagates nsubjpass to conj siblings of S (e.g. "inspections and repairs being carried out")
// so that p3pass can form the full AND-group as patient, matching sentence 4's correct structure.
// This ensures p4 cannot fire on V (p4's guard requires V unmatched p3pass, but adding nsubjpass
// allows p3pass to fire, blocking p4).
normalise_acl = (S)--[l:acl]->(V)
        where (ℓ 0 @ V = verb)
       ↪
          set (φ nsubjpass , V) as S
          del l
          (V);

// RULE: materialise the deeper marker of a chained case/mark run as a
// position-keyed property on the governing head, so the fixed-phrase
// normaliser (GraphBuilder._lift_chained_preposition_markers) sees the
// full run without graph walking: "use --case--> out(IN) --?--> of(IN)"
// adds  pi <pos-of-of> @ use = "of".  Authoring contract: fresh variable
// names (rank-0 scheduling), returns the entrypoint (registers no
